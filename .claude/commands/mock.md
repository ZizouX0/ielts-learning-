# Writing mock test — 60 minutes

This is a **test**, not a lesson. Behave like an invigilator, not a coach.

## Step 1 — Set both tasks at once

Read `progress/band-tracker.md` to avoid repeating recent task types, then
present **both tasks together, in one message**:

**Task 1** — a visual described in text (rotate the type: line graph, bar chart,
pie charts, table, process, map). Realistic, internally consistent figures.

**Task 2** — an original essay question from one of the five families.

State the conditions:

> **60 minutes total, starting now.**
> Recommended split: 20 minutes on Task 1, 40 minutes on Task 2.
> Task 1: minimum 150 words. Task 2: minimum 250 words.
> Task 2 is worth **twice** as much as Task 1 — if you run short, protect Task 2.
> Full sentences. Type both. Submit them together in one message.
> I will not answer questions until you submit.

## Step 2 — Enforce test conditions

**Give no help of any kind while I am writing.** No hints, no vocabulary, no
structure, no "are you on track?". If I ask a question mid-test, reply only:
*"I can't help during the test — keep writing."*

If I submit only one task, grade only that one and record the other as **not
attempted (band 0 for that task)**. That is what would happen on test day.

## Step 4 — Calculate the Writing band, showing the arithmetic

**Writing band = (Task 1 + 2 × Task 2) ÷ 3**, rounded to the nearest half band.

Show the working, e.g.:

> Task 1 = 6.0, Task 2 = 6.5
> (6.0 + 13.0) ÷ 3 = 6.33 → rounds to **6.5**

Then state plainly where this sits against my target of 7.0 overall, and what
Listening and Reading would need to be for a 7.0 with this Writing band (see the
routes table in `knowledge/tricks.md`).

## Step 5 — Analyse time management

Ask me how I split the hour and whether I finished. Then diagnose:
- Did Task 1 overrun and starve Task 2? (The most common and most expensive
  mistake — Task 2 is worth double.)
- Was either task under length?
- Was there any time left to check? On computer, the word count is on screen —
  did I use it?

## Step 6 — Errors and the one big fix

Quote and correct 5 sentences across both tasks, with the rule behind each.
Prioritise recurring errors from `progress/error-log.md` — recurrence under test
pressure is the strongest signal of what to drill next.

Then: **one** highest-impact fix.

No model answers after a mock. The point is the diagnosis; models come in
`/writing1` and `/writing2`.

## Step 7 — Log as MOCK and push

Append to `progress/band-tracker.md` with the type clearly marked **MOCK**, both
task bands, the weighted Writing band, and a time-management note.

Append errors to `progress/error-log.md` and any vocabulary gaps to
`progress/vocab-bank.md`.

Commit and push:
